# 换牌王（Card King）技术方案

> 版本：MVP 技术方案 v0.3（新增联机对战）
> 依据：PRD.md（MVP 产品设计文档，v0.2 记忆考验机制）

## 1. 目标与范围

- 实现 PRD 中 MVP 全部功能：热座 2~4 人本地同屏对战，支持 1 名真人 + 0~3 个机器人。
- **联机对战（v0.3）**：多台设备各自独立在线同局对战，每名玩家只看到自己该看的信息；一局 2~4 人，机器人 1~3 个（服务器托管）。本地热座模式保留。
- 规则引擎与 UI 分离，规则引擎为纯 TypeScript 模块，可独立单元测试；服务器复用同一引擎，保证单机/联机规则一致。

## 2. 技术栈

| 项     | 选型                             | 说明                    |
| ----- | ------------------------------ | --------------------- |
| 构建工具  | Vite                           | 开发快、热更新               |
| 语言    | TypeScript                     | 严格模式，核心类型安全           |
| UI 框架 | React 18                       | 组件化渲染牌桌               |
| 状态管理  | useReducer + Context           | 单一状态源，reducer 纯函数便于测试 |
| 样式    | 原生 CSS + CSS Modules           | 不引入 UI 框架，保持轻量        |
| 测试    | Vitest + React Testing Library | 与 Vite 同生态            |
| 联机通信 | `ws`（WebSocket）                | 服务器权威 + 每步全量视角推送      |
| 联机运行 | Node.js + `tsx`                | 直接运行 TypeScript 服务器   |

## 3. 整体架构

采用分层架构，核心层零 React 依赖：

```
┌─────────────────────────────┐
│  UI 层（React 组件）          │  MenuScreen / LobbyScreen /
│                             │  GameScreen / PlayerSeat /
│                             │  ActionPanel / LogPanel / ResultScreen
├─────────────────────────────┤
│  状态层（store）              │  本地：useReducer 持有 GameState
│                             │  联机：网络层接收服务器推送视图
├─────────────────────────────┤
│  核心层（core/，纯 TS）        │
│   types / deck / score       │  类型定义、牌堆、分数计算
│   engine（reducer）           │  状态流转 + 合法性校验（纯函数）
│   view（视角构造）             │  信息隐藏：按玩家 knowledge 渲染
│   ai（机器人策略）             │  决策输入=玩家视角，输出 Action
└─────────────────────────────┘
```

**核心原则**：`GameState` 是不可变数据，一切状态变化通过 `applyAction(state, action)` 纯函数产生新状态，保证可测试、可回滚、可重放。

### 3.1 联机架构（v0.3）：服务器权威

```
┌─────────────┐    WebSocket     ┌──────────────────────────────┐
│ 客户端 A     │ ───────────────▶ │  服务器（Node + ws）            │
│ (React+View) │ ◀─────────────── │  ├─ rooms.ts  房间管理          │
├─────────────┤                  │  ├─ engine    规则引擎（复用）    │
│ 客户端 B     │                  │  ├─ ai        机器人策略（复用）  │
│ (React+View) │                  │  └─ view      每玩家视角（复用）  │
└─────────────┘                  └──────────────────────────────┘
```

- **服务器权威**：所有状态变更、随机数、跟弃抢先判定、超时（跟弃 4s、翻看 5s、机器人延迟）都在服务器执行；客户端只提交 `Action` 并渲染服务器推送的视图。
- **信息隐藏物理隔离**：服务器为每名真人玩家单独生成视图（`buildView` + pending 牌面按查看者过滤），只推送该玩家该看的内容；对手手牌、牌堆内容、他人 knowledge 不下发到客户端。
- **机器人托管**：机器人由服务器驱动（AI 决策 + 随机反应延迟）。
- **房间与重连**：房间状态存服务器内存，房间码加入；刷新后凭 `localStorage` 中的房间码 + 座位号自动重连，牌局不丢。
- **MVP 部署形态**：电脑本机同时跑 WebSocket 服务器 + 前端，同一局域网/热点下手机浏览器访问 `http://电脑IP:端口`，多设备进同一房间对战；暂不做公网部署。

## 4. 数据模型

### 4.1 牌与分数

```
type Suit = 'spades' | 'hearts' | 'diamonds' | 'clubs';
type Rank = 'A' | '2' | ... | 'K' | 'JOKER_SMALL' | 'JOKER_BIG';
interface Card { id: string; suit: Suit | 'joker'; rank: Rank; }
```

分数规则（`score.ts`）：

- 大小王：0 分
- 红桃 K（suit=hearts 且 rank=K）：-1 分
- A~K：1~13 分

### 4.2 游戏状态

```
type Phase = 'deal' | 'playing' | 'follow' | 'final' | 'end';

interface GameState {
  deck: Card[];
  discardPile: Card[];
  players: PlayerState[];
  currentPlayer: number;
  phase: Phase;
  declaredPlayer: number | null;
  lastDiscard: Card | null;
  follow: FollowState | null;
  pending: PendingAction | null;
  lastSwap: { actor; selfPlayer; selfSlot; otherPlayer; otherSlot } | null;
  finalRemaining: number;
  winner: number[] | null;
  log: LogEntry[];
}

interface PlayerState {
  id: number;
  name: string;
  isBot: boolean;
  handSlots: (Card | null)[];   // 固定 4 个槽位，弃牌后不补；惩罚补牌满槽追加
  knowledge: Record<string, Card>; // 该玩家已确认看到的牌
  score?: number;
}
```

**槽位设计**：每个玩家固定 4 个槽位（对应"按固定顺序盖住"），弃牌 / 替换只影响槽位内容，位置保持不变；`null` 表示该槽位无牌。

### 4.3 信息隐藏设计（view.ts）

- 核心状态保存**真实牌面**（上帝视角，仅供结算和引擎校验使用）。
- 每个玩家持有自己的 `knowledge`（看过的牌，cardId → 牌面）。
- `buildView(state, playerId)`：从某玩家视角构造可见信息，UI 与 AI 都只消费该视角。
- 热座模式下 UI 始终按**当前行动玩家**的视角渲染；联机模式下服务器按**每名玩家各自**的视角分别推送。
- **记忆考验（v0.2）**：UI 层不再按 knowledge 长期展示牌面，平时一律渲染牌背（自己的牌也一样），仅在以下窗口强制正面（faceUp）：
  - 发牌看牌环节（当前玩家自己的 4 张）。
  - 翻看限时（7/8、9/10）：`pending = { kind: 'revealDone', card }`，牌面展示 5 秒（可提前点"收起"），到点自动 `REVEAL_DONE` 结束回合。
  - K 明换展示（`pending = { kind: 'confirmReveal' }` 的 selfCard / otherCard）。
  - 结算界面（ResultScreen 直接用真实手牌展开）。
- **联机日志安全化（v0.3）**：日志文本统一不写他人可反推的牌面（机器人查看不写牌面；真人查看自己的牌在日志中写"自己的一张牌"，不写具体点数），保证同一日志可下发给所有玩家。

## 5. 状态机与核心流程

### 5.1 阶段流转

```
setup（洗牌54张）
 → deal：每人发4张 → 各自看牌 → 盖牌确认（热座逐位确认；联机各自确认）
 → playing：当前玩家摸1张
     ├─ 功能牌：发动功能 / 弃牌 / 替换手牌
     ├─ 普通牌：弃牌 / 替换手牌
     └─ 可宣布定牌（任意时刻自己回合）
 → follow（弃牌后触发）：同分玩家跟弃竞争（每人每轮限一次）
     ├─ 成功者：弃掉同分牌（不补牌）
     └─ 失败者：惩罚，从牌库补1张牌
 → final（定牌后）：其余玩家按逆时针顺序依次操作一轮
     （不能再对已定牌玩家换牌）
 → end：全部展开手牌，总分最小者获胜；并列同时胜出
```

### 5.2 关键流程细节

**摸牌处理**：当前玩家从牌堆摸 1 张后必须选择：

- 发动功能（仅 7/8/9/10/J/Q/K）
- 直接弃牌（作为分数牌进弃牌堆，触发跟弃窗口）
- 替换手牌一张（被换下的牌进弃牌堆，同样触发跟弃窗口）

**跟弃竞争（follow，v0.2 重构）**：规则要求"速度最快者成功"，实现方案：

- 弃牌后进入跟弃窗口，窗口固定 **4 秒**，到点自动关闭、未操作者视为放弃（本地：UI 计时器对未决策真人派发 PASS_FOLLOW；联机：服务器计时器）。
- 每张手牌正下方常驻"弃"按钮（无机会提示、无同分高亮），点击 = `TRY_FOLLOW{ playerId, slot }`：满足"窗口开着 + 该槽位同分 + 抢先第一个提交"则跟弃成功（弃掉该牌）；**否则一律判定跟弃失败，从牌堆盲摸 1 张惩罚补牌**（含点错牌、窗口未开、抢弃太慢三种情况）。
- 机器人按随机延迟 0.5~2.5 秒自动尝试跟弃（有同分牌）或放弃（无同分牌）。
- 跟弃日志仅记录"XX 弃掉了 ♠5"与结果（成功/失败），不提示"可跟弃"，是否跟弃由玩家自行判断。
- 弃牌者本人也可参与跟弃（允许一回合内连弃两张同分牌）。

**定牌后终局**：`declaredPlayer` 定牌后，从其后一位开始按逆时针顺序，其余玩家各操作一轮（摸牌→处理，规则同正常回合，但换牌目标不能是定牌玩家），随后结算。

**牌堆耗尽**：若牌堆摸完仍未定牌，立即进入结算，手牌总分最低者获胜（并列同时胜出）。

### 5.3 动作类型（Action）

```
type Action =
 | { type: 'CONFIRM_DEAL'; }
 | { type: 'DRAW'; }
 | { type: 'USE_ABILITY'; }
 | { type: 'DISCARD_DRAWN'; }
 | { type: 'REPLACE'; slot: number }
 | { type: 'PICK_SELF_SLOT'; slot: number }
 | { type: 'PICK_OTHER'; playerId; slot }
 | { type: 'SWAP' | 'KEEP' }
 | { type: 'TRY_FOLLOW'; playerId; slot }
 | { type: 'PASS_FOLLOW'; playerId }
 | { type: 'REVEAL_DONE'; }
 | { type: 'DECLARE'; }
```

多步交互（如 K 明换：看牌 → 决定换 / 不换；换牌需选择自己和对方槽位）通过 `pending` 字段挂起，收到后续 action 后继续推进。

### 5.4 联机协议（v0.3）

```
客户端 → 服务器：
 { type:'createRoom', name, totalPlayers, botCount }
 { type:'joinRoom', code, name }
 { type:'startGame' }
 { type:'action', action: Action }
 { type:'restart' }
 { type:'rejoin', code, playerId, name }

服务器 → 客户端：
 { type:'joined', code, playerId, hostId, players }
 { type:'roomUpdate', code, hostId, players, canStart }
 { type:'gameStart', myId }
 { type:'view', view: ClientGameView }   // 每步全量推送（per-viewer 脱敏）
 { type:'error', message }
```

**ClientGameView（每玩家视角）**：

- `deckCount`（不泄露牌堆牌面）、`discardPile`（公开）、`players`（knowledge 清空）、`currentPlayer`、`phase`、`declaredPlayer`、`pending`（牌面按查看者过滤：drawn 仅当前玩家、revealDone 仅查看者、confirmReveal 仅发动者）、`lastSwap`（公开）、`winner`、`log`（安全化）、`view`（buildView 槽位视图）。

## 6. 机器人 AI（core/ai.ts）

- 输入：`buildView(state, playerId)` 的玩家视角。
- 输出：合法 `Action`。
- MVP 基础策略（与 PRD 第 4 节一致）：
  - **弃牌**：优先弃高分牌（J/Q/K、10~13），保留低分牌与大小王、红桃 K。
  - **功能牌**：
    - 7/8：查看自己 knowledge 中最不确定的牌。
    - 9/10：侦查分数可能最高的对手。
    - J/Q：用自己最高分牌暗换对手可能低分的牌。
    - K：先看双方牌，对方牌优于自己则换。
  - **定牌**：已知手牌均分 ≤ 2 时宣布定牌。
  - **跟弃**：同分牌存在时随机延迟尝试跟弃。
- 所有 AI 决策必须经过引擎合法性校验（`canApply`），非法则回退到保守动作。
- **联机（v0.3）**：AI 在服务器运行（复用同一 `aiDecide`），客户端不做任何机器人决策。

## 8. 测试策略

对应 AGENTS.md 要求，每次改动后更新 / 新增测试并全部通过：

1. **单元测试**：分数计算、各功能牌效果、跟弃竞争与惩罚、定牌终局、牌堆耗尽、非法操作拦截（如对已定牌玩家换牌）。
2. **状态守恒校验**：任意合法操作前后，全局牌数量恒为 54（牌堆 + 手牌 + 弃牌堆）。
3. **模拟对局测试**：所有玩家由 AI 代理，全自动跑完整对局 N 局（如 100 局），断言：流程必然终止、每步动作合法、结算正确。
4. **服务器测试**：房间创建/加入/满员开始/视角脱敏（非查看者拿不到牌面、knowledge 清空、日志不含他人牌面）。
5. **手动验收**：热座 2~4 人完整对局走查；联机双浏览器窗口走查完整对局与信息隔离。

## 9. 关键设计决策记录

| 决策   | 方案                       | 理由                                  |
| ---- | ------------------------ | ----------------------------------- |
| 状态管理 | 不可变 reducer 纯函数          | 可测试、可重放、可回滚，契合 AGENTS.md 的提交 / 回滚要求 |
| 信息隐藏 | knowledge 视角 + UI 强制背面 | knowledge 供 AI 决策，UI 平时一律牌背（记忆考验），仅翻看/发牌/结算窗口展示牌面 |
| 跟弃交互 | 手牌下方常驻"弃"按钮 + TRY_FOLLOW | 不提示机会、点错惩罚，考验玩家记忆与判断；窗口固定 4 秒防卡局 |
| 手牌槽位 | 固定 4 槽，null 表示空          | 符合"固定顺序盖住"，换牌 / 替换定位明确             |
| 样式   | 原生 CSS，不引 UI 框架          | MVP 保持轻量，避免依赖膨胀                     |
| 多步动作 | pending 字段挂起             | 统一处理 K 明换、翻看确认等需要多步选择的动作           |
| 联机权威 | 服务器权威 + per-viewer 推送     | 物理隔离信息泄露；规则/随机/判定单一来源，热座与联机一致 |
| 联机部署 | 电脑本机跑服务器 + 局域网/热点      | 零成本、免备案，契合当前热点联机场景；公网部署后续再做 |

## 11. 风险与对策

- **规则歧义**：MVP 口径已写入 PRD；实现中发现新歧义时先记录并在 PRD 更新后同步修改。
- **信息泄露**：UI 只渲染当前视角；结算前不允许任何玩家查看他人未公开牌面（除 9/10 功能）。联机模式由服务器 per-viewer 推送物理隔离，另以 server.test.ts 断言脱敏结果。
- **跟弃公平性**：热座下"速度"为近似竞争，机器人延迟参数可调；联机版为服务器裁决（抢先提交者胜），不同设备真实竞争。
- **断线**：房间状态在服务器内存，客户端刷新后凭 localStorage 自动重连；翻看/K 明换等挂起状态保留。
